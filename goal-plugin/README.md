# 持续目标 `/goal`（实验性）

基于 Codex 官方源码提交 [`340a18ed7cd0aea3bc218838d9ac1f0f30efb1ac`](https://github.com/openai/codex/tree/340a18ed7cd0aea3bc218838d9ac1f0f30efb1ac/codex-rs/ext/goal) 的运行机制，用 OpenCode V2 插件接口独立实现。不是桌面点击脚本，不调用 Codex 服务，不要求使用某个特定模型。

## 安装

需要 **OpenCode 2.2.7+**。沿用整个 Mod 的安装方式：退出 OpenCode 桌面端后，双击仓库根目录的 **`应用桌面端补丁.cmd`**；macOS / Linux 使用 `./apply-mod.sh`。

**不需要单独启动后端、不需要 `npm install` / `npm ci`，也不需要保留仓库路径。** 安装器使用随包提供的预构建产物，复制到：

```text
<全局配置目录>/desktop-mod-goals/release-<内容哈希>/
```

默认全局配置目录为 `~/.config/opencode`，也遵循 `OPENCODE_CONFIG_DIR` / `XDG_CONFIG_HOME`。安装脚本沿用整个 Mod 的 Node.js 18+ 要求；只有开发构建需要 Node.js 20.19+。

部署目录内有自包含服务端、RPC、GUI、最小 package manifest 及许可证，**没有源码链接和 `node_modules`**。安装器只在全局 `opencode.json(c)` 中登记该固定目录；运行时由 OpenCode 自带服务加载，不新增服务、端口或模型凭据。

保留已有配置、注释及其他插件，修改前另存带时间戳的备份。重复应用不会重复注册；旧独立安装器的源码路径经身份验证后自动迁移，不删除旧源码。安装/还原写入失败会尝试恢复本次操作前的配置和 ASAR；若发生并发编辑，拒绝覆盖，保留备份供检查。不会清空数据库或主动启动/重启后台服务。

仅安装目标功能的维护入口仍保留，但**普通用户无需单独执行**：

```sh
npm run goals:install
```

此维护入口同样只复制预构建文件，不运行 npm 安装、检查或构建，不修改 ASAR；由使用者确认当前 OpenCode 支持 2.2.7+。

OpenCode 自动重载配置后可用 `/goal`。整包补丁在输入框右下角增加目标图标，紧挨语音输入左侧；输入框上方的状态胶囊保留完整控制。GUI 与服务端来自同一个插件，不依赖原有 `/btw` 补丁。只使用目标插件维护入口、不应用 ASAR 时，仍可用 `/goal` 和命令面板创建目标，但没有输入框图标。

`opencode.json` 与 `opencode.jsonc` 可以同时存在，OpenCode 会依次读取两者。首次安装沿用 2.2.7 原生配置更新的文件选择规则：优先使用已有 `opencode.jsonc`，否则使用已有 `opencode.json`，两者都不存在才创建 JSONC。只向所选文件登记目标功能，不合并、删除或改写另一份配置；后续安装/还原沿用安装记录中的路径，避免配置文件后来新增而重复登记。

需要手动指定写入位置时仍可使用：

```sh
node apply-mod.mjs --goals-config "你的全局配置路径/opencode.jsonc"
```

也可用环境变量 `OPENCODE_MOD_CONFIG_PATH` 指定。低于 2.2.7、未知或预发布版本在整包安装时跳过目标功能，不猜测接口。安装后可以移动或删除源码目录；以后重新应用/还原时需要完整补丁包。

## 使用

### 输入框目标模式

1. 点击语音输入左侧的目标图标，不会弹出另一个输入对话框。
2. 输入框内显示「目标模式」小标签，输入目标后用原有发送按钮或 Enter 发送。目标文字最多 4,000 个 Unicode 字符，附件、引用、所选模型和 Agent 均沿用原生流程。
3. 发送成功后退出本次输入模式，后续消息默认是普通补充说明；已创建的持续目标不会因此停止。要暂停仍使用原生 Stop 或目标详情。

标签右侧的 × 或再次点击目标图标可取消本次输入模式，不清空草稿。模式按草稿隔离，切到其他会话不会误开启。Shell 与原生斜杠命令不被接管；Plan 不会自动切 Agent 或绕过执行限制。发送失败保留草稿和模式，附件/技能解析失败不会创建虚假运行目标。

同一会话已有未完成目标时，不会静默覆盖：在状态胶囊里编辑、恢复或清除原目标后再开始新目标。

### 斜杠命令与目标控制

```text
/goal 完成登录模块，保留现有权限规则，补充相关测试并确保构建通过
/goal
/goal pause
/goal resume
/goal edit 完成登录模块和退出登录流程，补充相关测试并确保构建通过
/goal budget 200000
/goal budget none
/goal clear
```

- `/goal <目标>`：明确创建并开始一个目标，最多 4,000 个 Unicode 字符。
- `/goal`：查看当前目标；不触发新一轮模型请求。桌面胶囊可查看完整详情。
- `pause`：停止自动推进，并中断当前原生执行；原生停止按钮也会暂停目标。
- `resume`：保留目标、用量及历史恢复运行；预算不足时需先明确提高或清除预算。
- `edit <目标>`：更新同一目标，保留用量和状态；旧版本工具结果不能结束更新后的目标。
- `budget <整数或 none>`：修改**总** Token 预算；不会自动恢复停止的目标。
- `clear`：撤销自动推进授权，不删除聊天、代码和其他插件设置。

输入框图标用于开启本次目标输入；状态胶囊用于查看、暂停、恢复、编辑、设置预算及清除，完成后也可开始新目标。正在运行的目标切换会话后继续执行；关闭目标详情不等于暂停。

**默认不限 Token，也没有隐藏的轮数上限。** 目标可能持续消耗所选模型的额度或费用。建议先用有限预算在小任务上试用；创建目标的当轮立即开始，需要从第一轮限制预算时，可通过插件 `control` RPC 同时传入 `tokenBudget`。桌面当前的新目标默认不限，开始后可在详情设置预算。

不要在第一次试用时授权不可逆操作。目标模式不会自动批准权限，不会切换模型、Agent 或扩展工具授权；原生权限审批与提问仍需你处理。它也不会自动创建多代理。

## 执行与停止

目标使用会话原生执行器，空闲前的 `experimental.idle` Hook 负责加入下一条内部队列消息，`resume: false`，不启动第二个执行器。原生执行器会重新检查输入队列。用户消息保持原来的附件、技能和 steering/queue 行为。

生命周期状态：

| 状态 | 含义 |
| --- | --- |
| `active` | 允许继续推进；可能正在等待原生权限、用户回答或后台工作 |
| `paused` | 用户暂停；必须明确恢复 |
| `blocked` | 模型报告持续阻塞，或运行时检测执行故障/连续空响应 |
| `complete` | 模型已通过目标工具报告完成与证据 |
| `budget_limited` | 已达到用户指定预算，不等于完成 |
| `usage_limited` | 已识别的供应商用量限制 |

模型直接获得 `get_goal`、`update_goal`，不依赖在自然语言中匹配「已完成」。后者需要当前目标 ID、修订号及证据；模型不能用它恢复、加预算或暂停。**为防止误开启，本版不提供模型侧 `create_goal`，创建只走用户明确开启的输入框目标模式、命令或 GUI/RPC。** 输入模式只给当前原生消息附加元数据，成功入队并被提升到模型上下文后才创建目标；不会重复发送第一轮，也不会因为旧聊天历史、清除后的重放或分叉而误建目标。这是与 Codex 的有意差异。

连续三轮没有可观察活动会停止自动续跑；原生执行失败也会停止。目标活动期间最多重试四次失败的模型请求，避免 OpenCode 的无限供应商重试一直耗时。等待仍在运行的原生后台任务时，不启动新模型轮询。正常非空回答不等于真实进展：本版与所参考的 Codex 一样，不能从任意任务自动证明「有进展」，仍依赖模型审查与预算。

完成审查要求对照完整需求检查当前文件、测试及其他真实证据，不允许缩水目标。受阻前要求连续三轮审查同一阻塞；程序保证最低轮数，**不会宣称已经可靠判定自然语言中的阻塞相同**。

## 用量与恢复

- 预算口径为 OpenCode 的 `input + output + reasoning + cache.write`，不计缓存读取。OpenCode 这些字段互不包含，不能直接照搬 Codex 对包容型字段的减法。
- 使用累计计数的差值记账，包含目标活动期间的原会话及后代会话用量；重放事件不重复记账。排除本 Mod 的独立只读 `/btw` 临时伴侣，不会把已暂停期间的普通聊天消耗加回目标。
- 模型调用和在途工具结束时可能超出预算；它是**执行边界上的续跑控制**，不是精确到单 Token 的硬额度，也不是账号配额预留。
- 目标存储在 OpenCode 服务端的插件持久存储，不依赖 `localStorage`。服务停止时不会继续运行；重新加载对应工作目录后，活动目标恢复状态，原生在途执行不重复启动。停机时间不累计为目标运行时间。
- Plan 模式不自动执行、不计目标用量；切回执行 Agent 后可用 `resume` 继续，不会自动切 Agent。
- 当前不把目标复制给分叉会话；原会话的目标不受分叉影响。会话移动到另一个目录时，需要新目录也加载此插件；不会由旧目录实例跨目录执行。

## 开发与验证

```sh
cd goal-plugin
npm ci --ignore-scripts
npm run typecheck
npm run build
npm test
```

真实 OpenCode 隔离测试（Node 22/24）：

```sh
node test/integration.mjs "OpenCode 2.2.7 的 CLI 可执行文件路径"
```

测试通过同一部署模块创建无 `node_modules` / 源码链接的安装目录，自动创建独立配置、数据目录和数据库，仅使用 loopback 假模型，不使用真实账号或付费模型。保留测试日志方便检查。`test/gui-preview.mjs` 可预览真实编译产物与 Solid；外壳控件是测试替身，**不能代替 Electron 桌面实机验收**。

发布前运行 `npm run build` 并携带完整 `dist/`。根目录 `npm test` 无需 npm 安装即可检查运行时和离线安装器；开发构建依赖仅在此子目录安装，不会复制到用户部署目录。

服务端接口与 GUI 接口包含实验性 API，OpenCode 升级后可能需要适配。已验证 2.2.7，不承诺所有未来版本自动兼容。

## 卸载

先暂停目标，再退出桌面端并双击 **`还原官方原版.cmd`**（macOS / Linux 用 `./restore.sh`），即可同时还原 ASAR 和移除目标功能注册。

只移除目标功能、不还原其他 Mod 的维护入口：

```sh
npm run goals:uninstall
```

只移除安装记录中由本补丁登记的路径，保留目标存储、会话、代码和其他插件。离线文件与备份也保留，避免误删用户内容。**重新安装后活动目标可能恢复，所以卸载前应暂停；卸载不等于把所有持久目标改成 paused。**
